# C0255 — Same byte compared in both arms against a per-arm constant: write compare and store per arm, ==0 arm first
tags: codegen,cross-jump,tail-merge,jump2,compare,if-else,arm-order,lb · date: 2026-10-25 · phase/task: 3.3/T34 · origin: W56 slus 800470EC

symptom: the target loads the same byte in both arms of a j-over-else. Each arm sets its own constant in v0, then one shared beq and sb follow.

lever: write the whole compare and its store inside each arm. gcc cross-jumps the identical tails into one beq and one sb. Put the `== 0` arm first so it is the fall-through.

## Instance
W56 slus func_800470EC (c32), match at try 5. One compare against a ternary constant gave 19 of 19 diff words. Per-arm compares in the wrong arm order gave 3 diff words.
The same tail appears in slus func_80046CAC (+0x84).
Two more W56 coders matched with a store per arm and the `== 0` arm first: slus func_8004F044 (c33) and slus func_800534B4 (c34). Those are C0165.

Related: C0165 (store per arm), C0196 (join store per arm), C0228 (one call per arm, merged).

Rider (T34.c50, `harvest.py rider`, strip = one compare against `obj[2] == 0 ? 0x26 : 0x3F`): load-bearing on slus func_800470EC (banked W56).
