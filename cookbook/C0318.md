# C0318 — Same byte tested twice, one test left: read the field fresh for the second test
tags: codegen,jump-thread,re-read,u8,local,test,branch,delay-slot,comma · date: 2026-11-06 · phase/task: 3.4/T24 · origin: W89 F5B58_ovl28

symptom: the target tests one byte field twice, with a different constant in each `beqz` delay slot. Ours tests the byte once, and the second branch is gone.

cause: a `u8` local tested twice holds one known value. gcc threads the second test into the first, so only one branch is left. A fresh field read is a new value, and the second test stays.

lever: if the target tests a byte twice, read the field again for the second test. Write `dir != 0 && (mask = 1, obj[0x15] != 0)`, not `dir` twice.

## Instance
W89 rockx5 func_800F5B58_ovl28 (c31) matched at try 6. A `u8` local tested twice gave 54 of 64 words in tries 1-4. The fresh read gave 3 words. The `mask = 1` set inside the test then gave the match. This is one datapoint.

The comma is not the lever. A separate `if (dir != 0) { mask = 1; }` before the test gives the same bytes.
Near: C0233 (read a field once into a `u8` local, the converse), C0307 (a fresh read of a source field).

## Byte proof
Rider (T24.c50, `harvest.py rider`, strip = `dir != 0` for the second test): load-bearing on rockx5 func_800F5B58_ovl28 (banked W89). The strip with the comma moved to its own `if` is inert.
