# C0285 — Block copies from one scratch base: reassign one src local per copy, address on one line
tags: codegen,regalloc,struct-copy,block-move,local,reuse,cse,base-pointer · date: 2026-11-01 · phase/task: 3.4/T11 · origin: W76 EEE24_ovl27

symptom: a function copies several blocks out of one scratch base with struct assignment. Ours has the wrong registers in the block-move loops, and each loop end is computed once.

cause: a user pseudo that lives past its block stays the canonical register for cse. Then the block-move source register is a separate copy, and each copy computes its loop end from the base.

lever: declare one `u8* src` and reassign it before each copy, with the address on one line: `src = D + 0x8C0; X = *(Blk20*)src;`. Do not split it as `src = D; src += off`, because that swaps the two hard registers.

## Instance
W76 rockx5 func_800EEE24_ovl27 (c1), four struct copies out of D_1F800028. Reuse of `src` in the later copies gave diff 114 to 46 of 199 words. One assignment per copy gave 26. The one-line `src = D_1F800028 + idx*32` matched at try 8.
Near: C0185 (a block-local base per block, the opposite case for plain field access), C0211 (re-read a pointer inline, no local).

## Byte proof
Rider (T11.c50, `harvest.py rider`, strip = the last two copies read the address inline, no `src`): load-bearing on rockx5 func_800EEE24_ovl27 (banked W76).
