# C0185 — One global addressed in two blocks: a block-local base pointer in each, not one reused
tags: codegen,cse,address,global,base-pointer,local,branch,split · date: 2026-10-24 · phase/task: 3.3/T16 · origin: W38 FAA4C EF604 FA4D0

symptom: one global array is addressed in a guarded block and again after the join. The target shares one `%hi` (lui in a0). It keeps two base registers: v1 inside the block, a1 after.

Ours has one `u8* p` assigned in both places. It reuses one register (a1) and schedules a constant lui late. With the global indexed directly, every access gets its own `%hi/%lo`. With `p = D` at function top (C0159), the lui hoists above an earlier test.

lever: two distinct block-local base pointers for the same global: `q = D;` inside the if-block, `p = D;` after the join. Each gets its own short live range off the shared `%hi`.

## Instances
W38 FAA4C_ovl46: one reused `p` (try 2) left 8 diff words, and `q` plus `p` (try 3) matched. W38 EF604_ovl01: block-local q plus p after the join went from 25 to 9 words. W38 FA4D0_ovl40: two locals before and after the join gave the base pair a3/s1.
Limit of C0159: a function-top pointer applies only when the target's lui sits above the branch.
Related: C0159 (one local base pointer across a branch), C0166 (index the global per use).

## Extension: spawned-object pointer per arm (W78)
Two arms or case groups each spawn an object and fill it with the same copy block. The target keeps the spawn pointer in `$a0` in one arm and in `$a1` in the other. One shared `u8* p` puts it in the same register in every arm. The lever is a separate pointer local for each arm or case group (`q = func_8002D078();` in one, `p = ...` in the other).

The W78 instances are rockx5 F984C_ovl04 (c7, `q` for cases 2-3), EF7E8_ovl06 (c4, `q` for arm 1) and F4094_ovl28 (c27, `q` in the else branch). In slus 8001F378 (c10), `o` is for the 5 head blocks and `obj` for the table blocks. Riders (T13.c50, strip = one shared local): load-bearing on all 4 (banked W78).
