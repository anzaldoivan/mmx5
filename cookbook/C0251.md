# C0251 — Byte classed by slt tests, ours folds a range to sltu: a switch with a GNU case range
tags: codegen,switch,case-range,slt,sltu,range,decision-tree,if-else · date: 2026-10-25 · phase/task: 3.3/T32 · origin: W54 slus 8003A134

symptom: a byte value is classified by signed `slt` tests (below K, below K2, equal K3). Ours folds the middle run into an `addiu`/`sltu` range test from an if/else-if chain.

cause: an `&&` range condition in an if folds to one unsigned compare. A switch expands its case list into a compare tree with no range fold.

lever: write a switch with a GNU case range (`case 0x25 ... 0x28:`). Too few cases for a jump table, so gcc emits a `slt` decision tree. The case order in source then sets the `bne`-to-default sense (C0072).

## Instance
W54 slus 8003A134 (c16), match at try 4. Nested ifs gave 21 of 23 words. The switch with the range case gave 7.
Zero-first arm tests gave 1. Moving case 0x2D above the range case matched.

Explicit labels `case 0x25: ... case 0x28:` give the same code as the range form. The switch is the lever, not the range syntax.

Related: C0151 (range fold of an if-condition), C0161 (stacked labels fold in a switch), C0072 (case order).

## Byte proof
Rider (T32.c50, `harvest.py rider`, strip = the switch as an if/else-if chain with `c >= 0x25 && c <= 0x28`): load-bearing on slus func_8003A134 (banked W54).
