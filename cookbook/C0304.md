# C0304 — Loop pointers in the wrong registers after a field store: read them back from the fields
tags: codegen,cse,store-forward,pointer,loop,copy,delay-slot,regalloc,field,re-read · date: 2026-11-02 · phase/task: 3.4/T19 · origin: W84 slus 80056458

symptom: a copy loop gets its pointers from two fields that the function stored just before. The target copies `src` with `addu x,v1,zero` in the `beqz` delay slot. It allocates `dst` to `$a0`, `src` to `$a1` and `n` to `$t0`. Ours keeps the computed pointers in other registers.

cause: CSE forwards a stored value to a later load of the same field. A local that holds the computed pointer is a separate pseudo, and local-alloc places it differently.

lever: store each pointer as a plain field store. After the byte stores, read the loop pointers back from the fields: `dst = *(s32**)(obj + 0x18); src = *(s32**)(obj + 0x14);`.

## Instance
W84 slus func_80056458 (c9) matched at try 9. The read-back took the diff from 36 words to the match. The form `dst[n] = src[n]` was worse, and the local declaration order was inert. This is one datapoint.
Near: C0202 (index a table by the stored field, not the local), C0292 (read a field again at every use).
