# C0220 — Byte state tested ==1, then slt <2, then ==0: nest the ifs, write the tail in both arms
tags: codegen,nested-if,switch,compare,order,cross-jump,tail,block-layout · date: 2026-10-24 · phase/task: 3.3/T23 · origin: W45 slus 80021434

symptom: the target tests a byte state for 1 first (`beq`), then `slt <2`, then 0. A switch always tests 0 first, whatever the type or case order. One condition `v < 2 && v == 0` folds the `slt` away.

lever: read the byte into an s32 local and nest the ifs:

```c
if (v != 1) { if (v < 2) { if (v == 0) { B; tail; return; } } } else { A; tail; return; }
```

For the block order B, tail, A (`j tail`), write the tail and a `return` in both arms. gcc cross-jumps A's copy into B's. One shared tail after the if gives the wrong order.
