# C0289 — One fewer saved reg with a shared fail label: write the error tail at each failure point
tags: codegen,cross-jump,jump2,cse,tail,goto,label,callee-saved,s-reg,regalloc · date: 2026-11-01 · phase/task: 3.4/T13 · origin: W78 slus 80015068

symptom: a function has one error tail at several failure points. The target saves one more callee-saved register than ours. It keeps hi-only copies (`move s0,a1`) and adds a fresh `addiu %lo` in the success block.

cause: with one `goto` label for the tail, cse links the earlier blocks to the tail. Then one value shares a register, and the function uses 5 saved registers, not 6. The gcc 2.95 cross-jump pass merges identical tails only after cse and gcse.

lever: write the full error tail at each failure point, with its own `return;`. Do not use one shared label. Jump2 merges the copies at the end. The copy that falls into the end label is the one that stays. So put each copy in the source position where the target keeps it.

## Instance
W78 slus func_80015068 (c44), three failure points with `func_80066D98(0); CdControlB(9, 0, 0); D_8009811C = 0x80;`. The written-out tails took the diff from 122 to 50 words. The tail order and the load order then matched at try 23.
Near: C0156 (a body written twice, merged by cross-jump), C0228 (one call per arm, merged by gcc).

## Extension: one assignment at each failure point (W79)

Then jump2 cross-jumps the case 1 and case 2 calls into one `jal`. This took the diff from 72 to 3 words. A shared label with `goto` never merged the calls.
