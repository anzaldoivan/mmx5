# C0078 — Table entry via pointer-plus-index (T + i)->f flips the addu base/index regs
tags: idiom,cse_expr,addressing,operand-order,index,array-ref,stride-12,addu · date: 2026-10-06 · phase/task: current/T7 · origin: docs/codegen-map/levers.yaml expr_ptr_plus_index

symptom: table lookup `addu` with base and scaled-index registers swapped (12-byte entry, non-power-of-2 stride)
lever: expr_ptr_plus_index

## Residual
`T[i].f` on a 12-byte entry: ours puts the base in the first register and adds into it; the target adds into the scaled index's register. tell regex (levers.yaml `expr_ptr_plus_index`): `^\s*sll\s+\$2,\$5,1\b` -- matches ours (before), absent in the after. Game: rockx5 func_800EF5D8_ovl02, func_800EF81C_ovl02, func_800EF714_ovl02 (table D_800F43AC_ovl02, `Ent43AC`).

## Mechanism
Pass group `cse_expr`. The array ref (`gcc/c-typeck.c:1384 build_array_ref`) and pointer-plus-int (`pointer_int_sum`) build different trees for the same address; expansion order of the base and the x12 shift-add sequence differs, so local-alloc births the base and index pseudos in the other order. Complement of C0059 (power-of-2 stride, MULT first).

## Lever
write `(T + i)->f` (or `(i + T)->f`, which also flips the addu operand order) instead of `T[i].f`; the byte-pointer form `((E *)((u8 *)T + i * 12))->f` gives the same codegen (EF714).
