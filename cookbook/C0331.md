# C0331 — Loop constant hoisted into a saved reg, target keeps li in the loop: a dead second set of the local
tags: codegen,loop,invariant,hoist,constant,li,saved-reg,local,FAKE,consec-sets · date: 2026-11-07 · phase/task: 3.4/T28 · origin: W93 slus 8003D9A8

symptom: a loop uses a constant, and our build hoists it into a saved register. The target loads the constant with `li` inside the loop.

cause: loop.c moves a register out of the loop only when it has one set in the loop, or consecutive invariant sets. The test is `consec_sets_invariant_p` (refs/gcc-2.95.2-psx/gcc/loop.c:884, 3327). A second set of the register later in the loop stops the move. Flow deletes a dead second set after the loop pass.

lever: if a loop constant is hoisted and the target keeps it in the loop, put the constant in a local. After the use, add a dead second set `m = 0; // !FAKE:`.

## Instance
W93 slus func_8003D9A8 (c38) matched at try 14. The body was correct from try 1. The only residual was `-0x80` in s2. The loop body is `m = -0x80; func_8003DAA4(t | m); m = 0;`.

Inert or worse: a goto loop, a `do {} while (0)` wrapper, an `s8` callee with `| 0x80`, padding locals, and a forward goto into the loop body. A live second set `m |= t` also stops the hoist, but it schedules `li` before `andi` (2 words).
Near: C0056 (invariant load at the loop head), C0257 (order of two hoisted invariants).
