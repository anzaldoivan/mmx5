# Dedup registry: one entry per (sig, body), so a census group can hold two byte-twin sub-clusters

- Census dup groups mask relocations. One group can therefore hold two sub-clusters that are byte twins inside each and differ between them (raw words, addends). Each sub-cluster needs its own shared body.
- Since 3.5 T4.c11 (86b49338), config/dedup.us.yaml holds one block per (group sig, body). `register()` appends to the block whose sig and body both match, and otherwise adds a new block.
- Own-C banks that twin each other show as `dedup: unregistered`. Fix: give the rep's body to src/shared/<rep>.c (propagate's rep step), make the twins include it, then run `propagate.py run src/shared/<rep>.c`. That run needs the body file to exist and a `make split BINARY=<a>` first. `--dry-run` copies the worktree from HEAD, so it does not see an uncommitted revert.
- Before c11, a second block with the same sig was merged into the first one. Its members then showed as `ungated`.
