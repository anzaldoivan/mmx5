# C0292 — Field tested in v0, copied in the delay slot: read it at every use, same narrowed width
tags: codegen,gcse,reload,copy,delay-slot,u16,mask,mode,local,re-read · date: 2026-11-01 · phase/task: 3.4/T14 · origin: W79 F1630_ovl06

symptom: the target loads a field once and tests it from `$v0`. In the branch delay slot, it copies the value into an argument register (`lhu v0; andi; bne; addu a2,v0`). With a local for the field, ours coalesces the copy or loads the field again.

cause: gcse replaces the later reads of the field with a copy of the first read. That copy is the delay-slot `addu`. All the reads must have the same narrowed mode. The test `x & m` with an `s32` mask `m` is in SImode, so gcc loads the field again for it.

lever: read the field directly at every use, with no local: `*(u16*)(o + 0x88)`. Declare a mask local `u16`, not `s32`. Then `u16 & u16` narrows like the literal masks `& 7` and `& 0x100`.

## Instance
W79 rockx5 func_800F1630_ovl06 (c44), match at try 20. Locals for the field all coalesced or reloaded. These were plain locals, temp copies, a dead reset (C0070) and a copy per arm (C0207).
W79 rockx5 func_800F22D8_ovl11 (c37) is a second datapoint for the inline read: `(*(u8**)(o + 0x68))[i]` at every use, with no pointer local.
Near: C0150 (a re-read u8 field gives an `andi` for each use), C0211 (a pointer read inline per block).
