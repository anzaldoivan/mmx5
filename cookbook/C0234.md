# C0234 — Independent store pair in the wrong order: write it in the reverse of the asm's order
tags: codegen,sched,store-order,reverse,global,rmw,v0-v1,statement-order · date: 2026-10-25 · phase/task: 3.3/T27 · origin: W49 FA390 FADFC F8920 slus 80019BD4

symptom: two independent stores (or two global read-modify-writes) come out in the opposite order to ours, or with v0/v1 swapped on their loads. Ours wrote them in the asm's order, as C0051 says. W49 FA390_ovl47 (`D_80093E68 += 0x400; D_8009A42E += 0x20;`, the asm order) had diff 2 of 29 words.

lever: write the pair in the reverse of the asm's order. In these cases gcc's scheduler emits the later statement first, so source order B, A gives asm A, B. Try it when the C0051 order (the target's order) fails with a pure order or v0/v1 diff.

## Instances
W49 FA390_ovl47 (c42) and FADFC_ovl58 (c44): `D_8009A42E += 0x20` written before `D_80093E68 += 0x400` matched at try 2.

W49 F8920_ovl09 (c14): the store to +0x50 written before +0x68. The asm stores +0x68 first. Try 1 in the asm's order had diff 2.
W49 slus 80019BD4 (c20): in a loop body, two groups of stores (zero two tag banks, then link them). The asm order (links first) had diff 22 of 30. Zeros written first matched.

Related: C0051 (the opposite direction: ties keep source order), C0177 (an equal-constant pair: chained assignment), C0086 (sweep the orders offline).
