# C0279 — Byte zero test folds to beq, no lone sll 24: hold the byte in a one-byte struct local
tags: codegen,u8,s8,sll,sign-extend,struct,QImode,promote,local,FAKE · date: 2026-10-31 · phase/task: 3.4/T8 · origin: W73 slus 8003EC00

symptom: a byte is copied to a field, then tested for zero, then used again for `+ 9`. The target has a lone `sll 24` before the `beqz`, and one register feeds the `+ 9`. Ours folds the test into `beq` on the byte, or reloads the byte.

cause: gcc promotes a scalar `u8` or `s8` local to a full register. Then combine knows the value is 0..255 and folds the sign test. A struct is not promoted, because `PROMOTE_MODE` covers scalars only. A one-byte struct local stays a `QImode` pseudo, and the sign extension gives `sll 24` (the zero test drops the `sra`).

lever: hold the byte in a one-byte struct local. Write `QByte v; v.b = p[0x93]; p[0x94] = v.b; if ((s8)v.b != 0) ... p[0x94] = v.b + 9;`. Mark the local `// !FAKE:`. Lift the typedef `typedef struct { u8 b; } QByte;` into `include/types.h` before the bank.

## Instance
W73 slus func_8003EC00 (c45) matched at try 12. A `u8`, `s8` or `s32` local, an `s8` view of the stored field, and `(v << 24) != 0` all folded to `beq`. No local gave the `sll` but reloaded the byte.
