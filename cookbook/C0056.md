# C0056 — Invariant load stays at loop head unless the operand is const
tags: idiom,loop,loop,invariant,hoist,preheader,const,global-reload · date: 2026-10-05 · phase/task: 1.7/T7 · origin: docs/codegen-map/levers.yaml loop_const_hoist

symptom: invariant load at loop head vs hoisted to preheader
lever: loop_const_hoist

## Residual
The residual is an invariant load at the loop head vs hoisted to the preheader. The tell regex (levers.yaml `loop_const_hoist`) is `^\$L\d+:\n\s*lw\s+\$2,%lo\(K\)\(\$\d+\)`. It matches ours (before) and is absent in the after.

## Mechanism
In pass group `loop`, a call in the loop sets unknown_address_altered. Thus a plain global is not invariant, and the code reloads the global each iteration. The pass accepts RTX_UNCHANGING_P (`const`) before that test and hoists the load. Cite: `gcc/loop.c:3254 RTX_UNCHANGING_P` (staged tree refs/gcc-2.95.2-psx/). Map: docs/codegen-map/loop.md L4.

## Lever
The lever is the `const`/volatility of the operand. `extern const int K` hoists to the preheader. `extern int K` reloads at the loop head.
