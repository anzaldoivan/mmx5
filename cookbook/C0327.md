# C0327 — Pointer param moved from a0 at entry: a fresh pointer local live only in the reload block
tags: codegen,regalloc,local-alloc,param,a0,a3,entry-move,local,for,init · date: 2026-11-07 · phase/task: 3.4/T27 · origin: W92 slus 80056604

symptom: the target moves a pointer param from `$a0` to `$a3` at entry with `addu a3,a0,zero`. Our build keeps the param in `$a0`.

cause: local-alloc runs before global alloc. A pointer local that lives only in one block is allocated first and takes `$a0`. The param then loses `$a0` and gets the entry copy.

lever: if a field is reloaded in one block, read it into a fresh pointer local used only in that block. Do not reuse a local from an earlier step. If a loop counter outranks the wrong reg, set it in the `for` header, not before an earlier test.

## Instances
W92 slus func_80056604 (c6) matched at try 7 of 20. Tries 1 to 5 had the right structure but `obj` stayed in `$a0`. Param reuse, one local for the reload and the source, and a static inline body were inert. At try 6, a fresh `cur = *(u8**)(obj + 0x1C)` used only in the copy block moved `obj` to `$a3`. At try 7, `n = 0` in the `for` header shortened the counter's life.
Near: C0052 (single-set temp gets the birthing boost), C0221 (counter init in the `for` header).
