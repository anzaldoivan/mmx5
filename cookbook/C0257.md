# C0257 — Two loop invariants hoisted in the wrong order: read the first one into a local, in target order
tags: codegen,loop,invariant,hoist,prologue,saved-reg,local,table-call · date: 2026-10-25 · phase/task: 3.3/T34 · origin: W56 slus 80020904

symptom: a loop has two invariants hoisted into saved registers, and ours sets them up in the other order. The order shows in the prologue.

lever: the hoisted invariants come out in the order they first appear in the loop body. Split the expression so the symbol the target sets up first is read first. Here a state byte read into an `s32` local before the table call does it.

## Instance
W56 slus func_80020904 (c28), match at try 3. The inline `D_8007108C[D_800D1C00[0]](D_800D1C00)` gave 5 of 19 diff words with the table base first. Swapping the extern order changed nothing.

Related: C0056 (invariant load at the loop head), C0206 (loop bound invariant).
