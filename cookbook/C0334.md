# C0334 — Constant-row table read flat adds in the wrong order: declare D[][N], index D[k][i]
tags: codegen,array,2d,row,table,index,u8,add-order,giv · date: 2026-11-07 · phase/task: 3.5/T1 · origin: W95 FB030_ovl07 EF124_ovl12 F9180_ovl06

symptom: a byte table read at a constant row and a variable column (`row 0` or `row 1`, column `f() & 0xF`). A flat index `D[i + 0x12]` gives the addu operands in the wrong order, or loop.c merges the arms into one giv. A pointer form gives `%hi(D+18)`.

lever: declare the table 2-D with the row length, `extern u8 D[][0x12]`, and index `D[0][i]` / `D[1][i]`. The same works for a local struct view, `struct { s16 a[3][5]; }` read as `t.a[1][i]`.

## Instance
W95 rockx5 func_800FB030_ovl07 (c45): flat `[r + 0x12]` 192 words, 2-D `[0][r]`/`[1][r]` 12 words, then match.
W95 rockx5 func_800EF124_ovl12 (c46): flat `a[i+5]`/`a[i+10]` 103/218 words, 2-D `a[1][i]`/`a[2][i]` match. 2-D keeps `sll i,1` + `addu sp` per arm.
W95 rockx5 func_800F9180_ovl06: `extern u8 D[][0x12]` indexed `[0..2][f()&0xF]`, 134 -> 122 words.
