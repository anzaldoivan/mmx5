# C0297 — Stored byte indexes a table in each arm: re-read the stored field, jump2 shares the tail
tags: codegen,cse,store-forward,andi,0xff,table,index,cross-jump,jump2,if-else · date: 2026-11-01 · phase/task: 3.4/T16 · origin: W81 F24C4_ovl07

symptom: each arm of an if/else stores a byte, then indexes a byte table with it. The target has `sb`, then `andi 0xFF` on the stored register, then the table `lbu`. jump2 shares the `addu`, `lbu` and `sb` tail at the join. Ours puts the `lui` of the table after the `andi`, or it merges the `sb` and `andi` tails.

cause: cse forwards the stored value to a later read of the same field. The read becomes `andi 0xFF` on the stored register. The table access is then the same in each arm, and jump2 cross-jumps it.

lever: in each arm, store the byte from an `s32` local, then read the stored field back as the index. Write `obj[0x82] = d; obj[0x47] = D_tbl[obj[0x82]];` in each arm. Do not index by `(u8)d`, by `d & 0xFF` or by a table local.
