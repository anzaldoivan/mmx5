# C0296 — Spill reload in the wrong scratch reg: keep a call result live across the reload point
tags: codegen,regalloc,spill,reload,local-alloc,call-value,statement-order,v0,a0 · date: 2026-11-01 · phase/task: 3.4/T16 · origin: W81 F7024_ovl01

symptom: a value spilled to the stack is reloaded in the loop. The target reloads it into `$a0`. Ours reloads it into `$v0`.

cause: local-alloc gives the reload the first free scratch register. When no other value is live at the reload point, that register is `$v0`.

lever: keep a call result live across the reload point in source order. Assign the results to `s32` locals first (`hi = f(); lo = f();`). Then write the statement that reloads the spilled value (`dx = x2 - x;`). Then use the results (`ry = (hi << 8) + lo + 1;`). `lo` stays in `$v0` at the reload, so the reload takes `$a0`. sched2 restores the target order.

## Instance
W81 rockx5 func_800F7024_ovl01 (c5) matched at try 7. Try 6 had 2 words of diff, and the residual was the reload register of `dx`. A computation of `dx` before the calls gave 102 words. `dx` and `dy` assigned together gave 18 words. This is one datapoint.
