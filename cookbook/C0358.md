# Two arm locals in swapped v0/v1: return the one the target keeps in v0

Tell: two locals, each set in both arms of an if/else, come out with v0 and v1 swapped. Declaration order (C0046) and
statement order do not fix it. At `jr ra`, the target still holds one of them in `$2`.

Move: give the function an s32 return type and `return v;` for the local the target keeps in `$2`. The return copy
gives global-alloc a `$2` preference for that local. The instructions do not change, because the value is already in
`v0` at the return. Set both locals in each arm with no default before the `if`. Put the first instruction of each
arm in the target's delay-slot order.

Use only on a placeholder (`func_`) whose callers do not read a void result. A named function keeps its prototype.

Evidence: 3.6 T5 W102 rockx5 func_800F3668_ovl00 went from diff 6 of 19 to a match on try 12. This is one datapoint.
Related: C0254 (return in place), C0069 (callee return type).
