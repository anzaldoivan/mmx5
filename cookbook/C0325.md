# C0325 — Pointer stored to a global then used, lui/sll regs off: a chained assignment G = p = expr
tags: codegen,regalloc,chained-assignment,global,pointer,lui,sll,v0-v1,delay-slot · date: 2026-11-07 · phase/task: 3.4/T26 · origin: W91 slus 80016490

symptom: a computed pointer is stored to a global and then dereferenced. Our `lui` and `sll` take the wrong registers, and the next two delay slots differ.

cause: two statements make the global store a separate use of the local. The chained form assigns the global from the same value in one expression. That changes the pseudo order, so regalloc gives the `lui` `$v0` and the `sll` `$v1`.

lever: if the global store and the local need other registers, chain them. Write `G = p = expr;`, not `p = expr; G = p;`.
