# C0321 — Multiply by 0x60 folds to (x*3)<<5: write t = s << 4 alone, then ((s << 5) + t) << 1
tags: codegen,multiply,shift,sll,addu,synth,constant,statement-split,local · date: 2026-11-07 · phase/task: 3.4/T25 · origin: W90 slus 8004A610

symptom: the target multiplies by 0x60 as `sll 5`, `sll 4`, `addu` and `sll 1`. Ours computes `(x * 3) << 5` from `x * 0x60` or `x * 48`.

cause: gcc synthesizes a constant multiply with its own shift-add sequence. That sequence does not give the target's order. A shift in its own statement is a separate pseudo, so gcc keeps the target's sum.

lever: if a multiply by 0x60 gives the wrong shift-add, write the shifts. Write `t = s << 4;` as its own statement, then `((s << 5) + t) << 1`.

## Instance
W90 slus func_8004A610 (c1) matched at try 10. `x * 0x60` and each form of `* 48` folded to `(x * 3) << 5` (tries 4 and 9). The second scale uses the same shape with a fresh temp `u` and a fresh local `c`. A reused `s` or `t` for the second scale was worse. This is one datapoint.

The full-statement form `s = (s << 5) + t;` moved the `addu a0,s1` below the sum (8 words).

## Byte proof
Riders (T25.c50, `harvest.py rider`): load-bearing on slus func_8004A610 (banked W90). Strip 1 = `((s << 5) + (s << 4)) << 1` inline. Strip 2 = `s * 0x60`.
