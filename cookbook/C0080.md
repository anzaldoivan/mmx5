# C0080 — Abs-window test: a condition ternary keeps the negative arm out of line, one store tail
tags: idiom,cse_expr,abs,ternary,cross-jump,branch,bltz,window · date: 2026-10-06 · phase/task: 1.8.2/T15.1 · origin: current/T14 c15

symptom: abs-window test `|a-b| <= lim` guarding one store block: ours `bgez d` with both arms cross-jumped into one shared `slt`/branch; target `bltz d` to an out-of-line negative arm, store block shared once
lever: cond_ternary_abs_window

Write the window test as one condition ternary: `if ((d >= 0) ? (d <= lim) : (b - a <= lim)) { store }`. Do not write `if (d >= 0) { if (d <= lim) store } else if (b - a <= lim) store`, nor an if/else-return form.

Nested if / if-else (either arm order): both compares cross-jump into a shared compare tail (`bgez` + one `slt`). The store block is duplicated or merged differently.
Ternary in the condition: the result is one jump tree with the negative arm out of line (`bltz`). Each arm has its own compare, and there is a single store tail.

Tell: the target branches `bltz d` forward to a recomputed `b - a` (not `negu d`) and has one copy of the guarded stores.
Related: C0079 (abs per arm in stores), C0050 (cross-jump law).
