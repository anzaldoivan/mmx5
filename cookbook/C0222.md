# C0222 — Byte loop walking down from base+N with bgez: write the plain up-count, gcc reverses it
tags: codegen,loop,reversal,up-count,down-count,strength-reduction,bgez,byte-clear · date: 2026-10-24 · phase/task: 3.3/T23 · origin: W45 F0DC0

symptom: a byte-zero loop where the target counts 8 down to -1 (`bgez`) with a pointer at base+8 (its own `addiu +8`) and stride -1. A count-down `D[i]` loop is not strength-reduced (31 words, an indexed `addu`).

lever: write the loop counting up: `for (i = 0; i < 9; i++) D[i] = 0;`. gcc reverses the counting-only index (C0054, C0055) and walks the pointer down from base+8. Rule: a target that walks down from base+N came from an up-count. A target that walks up from base came from `D[N-i]`.

## Instance
W45 rockx5 F0DC0_ovl20 (c19), matched on try 7. Rejected: `p = D+8; *p--` folds to `%hi(D+8)`. `D[8-i]` counting up gives 29 words, base+0 stride +1.

## Byte proof
Rider (T23.c50, `harvest.py rider`). Strip = `for (i = 8; i >= 0; i--)`. Load-bearing on rockx5 func_800F0DC0_ovl20 (banked W45).
