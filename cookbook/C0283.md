# C0283 — Case cross-jumped into a shared byte increment: do the RMW through the switch-value local
tags: codegen,cross-jump,tail-merge,jump2,switch,rmw,local,v0-v1,increment · date: 2026-11-01 · phase/task: 3.4/T10 · origin: W75 slus 80034D18

symptom: a switch case increments a byte field, and a shared block increments the same field. The compiler cross-jumps the case into the shared block, because both use the same registers after the reload. A `goto` layout with `// !FAKE:` labels does not stop the merge.

lever: in the shared block, do the read, the increment and the store through the switch-value `s32` local: `t = o[6]; t++; o[6] = t;`. The local keeps the switch register (`v1`), and the other case keeps `v0`. The tails differ, so the compiler does not merge them.

## Instance
W75 slus func_80034D18 (c10, jump table jtbl_80010E98). A plain `o[6]++` in the shared block gave diff 36 of 61 words. `t = o[6] + 1; o[6] = t;` gave diff 2 of 61. The three-statement form matched at try 6.
Near: C0092 (a call result stops a tail merge), C0276 (the RMW first in one arm).
