# C0152 — Per-branch stores, no join variable: keep each arm's tail from cross-jumping
tags: codegen,cross-jump,tail-merge,jump2,join-variable,per-branch,store-order · date: 2026-10-19 · phase/task: 3.2/T3 · origin: .run/p32t3/c28 (W23 harvest)

symptom: target keeps a store (or `lbu` and increment) in each branch. Ours merges the arms' tails or schedules the load after the join.
lever: per-branch statements, no join variable

## Residual
slus func_8003B33C (100 insns) had a join var `v` for the 0x3C store. Then jump2 merged the two inner arms' tails. The compiler moved the `li` into the delay slot.
In rockx5 func_800F1BDC_ovl26, `o[6]++` after the if/else gave diff 16 of 47 (`lbu` scheduled after the join).

## Mechanism
A value set in each arm and stored once after the join makes the arms' last insns identical. The jump2 pass cross-jumps them, and reorg fills the delay slot from the merged tail.
A statement after the join is scheduled in the join block. A store (or increment) written in each arm stays in that arm's block. gcc builds any merge itself where the target has one.

## Lever
Write the store or `x++` at the end of every arm. Keep the target's statement order (here 0x38, 0x3C, 0x155). Use no join variable.
Do the reverse when the target shows one merged tail. Related: C0050, C0092.
