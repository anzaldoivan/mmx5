# A zero store pinned above a global load: declare the global `extern const`

Tell: a store (often a C0129 zero-store spacer) sits above the `lhu`/`lw` of a global in our asm. The target has the
load first and the store after it. Store reorders, fences (C0294) and constant locals fix the registers or the order,
never both.

Move: declare the global `extern const <type> D_x;` in the draft. GCC treats a const object as unchanging memory, so
the store no longer may alias the load. The sched2 pass is then free to sink the store below the load, as the target does.
The store still acts as the register spacer (C0129), so the `%hi` lui keeps its register.

Keep the type the card's consensus gives. Add only `const`. Other files keep their plain declaration (asm owns the
data, so no definition conflicts). The whole-binary SHA at the gate is the proof.

Evidence: 3.6 T5 W102 rockx5 func_800F03F4_ovl04, the W39 draft with `extern u16` changed to `extern const s16`,
matched on try 17. One datapoint. Related: C0056 (const keeps an invariant load), C0129.
