# C0291 — Tested-zero byte set to 1 holds 1 in a saved reg: store the s8 local plus one
tags: codegen,cse,constant,s8,local,increment,callee-saved,delay-slot,frame · date: 2026-11-01 · phase/task: 3.4/T14 · origin: W79 F0568_ovl06

symptom: a byte field is tested for zero and then set to 1. A second store in the function also writes 1. The target has `li 1` in the branch delay slot. Ours keeps the constant 1 in a saved register across a call, with a larger frame (0x20).

cause: two stores of the literal 1 use the same constant. Then cse can give both stores one pseudo, and the pseudo lives across the call in a saved register. The sum `v + 1` is not the literal at cse time. So it probably does not share that pseudo.

lever: read the field into an `s8` local, test the local, and store the local plus one.
`s8 v = obj[6]; if (v == 0) obj[6] = v + 1;`
