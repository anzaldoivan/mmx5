# C0273 — Range test of a byte local loses andi 0xFF: reuse the s32 local for a full-width value
tags: codegen,andi,0xff,u8,s32,local,reuse,combine,nonzero-bits · date: 2026-10-31 · phase/task: 3.4/T7 · origin: W72 F0004_ovl08

symptom: the target keeps `andi 0xFF` on a byte local before a range test (`sltiu 0x11`). Ours drops the mask in every spelling: `u8` or `s32` local, `& 0xFF`, a re-read of the field (C0150).

lever: reuse the same `s32` local for an unrelated full-width value later in the function. For example, write `t = *(s32*)(obj + 0x30); *(s32*)(p + 0x30) = t;`.

## Mechanism
The local is set only by `lbu`, so combine knows its range is 0..255 and deletes the mask as redundant. Each variable keeps one pseudo in gcc 2.95. A second, full-width set merges into the nonzero bits of that pseudo, so the mask stays. The reuse site also moves regalloc, so try each candidate copy.

## Instance
W72 rockx5 func_800F0004_ovl08 (c3) matched at try 18. Tries 1-15 lost the `andi`. Reuse at the 0x7C decrement gave diff 9 and reuse at the 0x20 multiply gave diff 6. Reuse at the 0x30 copy matched.

## Byte proof
Rider (T7.c50, `harvest.py rider`, strip = the 0x30 copy without `t`): load-bearing on rockx5 func_800F0004_ovl08 (banked W72).
