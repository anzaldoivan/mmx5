# C0320 — Table index in the wrong reg after an if/else: set it in each arm, not before the if
tags: codegen,regalloc,index,local,if-else,preset,conflict,a0 · date: 2026-11-07 · phase/task: 3.4/T25 · origin: W90 EF4D8_ovl10

symptom: a local index is set to 0 or 1 by an if/else and then indexes a table. Ours has the index in `$a2`. The target has it in `$a0`, and the last words differ.

cause: a preset `side = 0;` before the `if` lives across the compare. It then conflicts with the field temp of the compare in `$a0`. Set inside the then-arm, its live range starts after the compare.

lever: if the index register is wrong, set the index in each arm after the compare. Write `if (a < b) { side = 0; ... } else { side = 1; ... }`, not `side = 0;` before the `if`.

## Instance
W90 rockx5 func_800EF4D8_ovl10 (c16) matched at try 11. One base local per block (C0185) took the diff to 3 of 61 words. Then `side = 0;` inside the then-arm closed the last 3 words. This is one datapoint.

The lever needs the per-block base locals. With one base local, it gave 57 of 61 words.
Near: C0185 (a base local per block), C0306 (a constant set inside an if).
