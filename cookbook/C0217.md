# C0217 — Global set from a byte, read in both arms: read the global, not a local copy (lbu+sll+sra kept)
tags: codegen,global,local,reload,lbu,sll,sra,if-else,s16 · date: 2026-10-24 · phase/task: 3.3/T22 · origin: W44 slus 80030D88

symptom: an s16 global is set from a sign-extended byte (`G = (s8)p[0]`) and then read in both arms of an if/else. The target reads it again as lbu+sll+sra. A local copy of the value gives a lone lb and wrong regs.

lever: in the arms, read the global directly (`y + G`), not a local copy. Write a later sum of two globals (`G1 + G2`) from the globals too. Then gcc reloads it at the join with lhu, as the target does.
