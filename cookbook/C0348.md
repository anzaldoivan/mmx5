# propagate's #include member text hides the body's externs from carve: rodata cut, SHA red

Problem: a masked-only twin passes propagate's masked compare, but the whole-binary SHA is red (`ROCK_X5.BIN: FAILED`).
The member text is `#define DEDUP_NAME <m>`, the rename `#define`s and `#include "../shared/<rep>.c"`.
carve.py reads `--body` to find region labels that the C declares `extern` (C0131).
The externs are in the included body, so carve does not see them.
It cuts the twin's region data into a `[<off>, .rodata, <name>]` span, and the C never emits those bytes.

Detect: run `carve.py plan <a> <vram> --module ovlNN --body <member text>`.
A `.rodata` line in the plan that is not there with a standalone copy is the cut.

Fix: bank the twin as its own C, a copy of the rep body with the twin's symbols (C0264).
The copy declares the data `extern`, so carve cuts only the `c` subsegment.
Ex (3.5/T4): rockx5 func_800FD9E8_ovl31 (W71 twin of func_800F69FC_ovl03), func_800FD14C_ovl31, func_800FEE9C_ovl31.
Also func_800EF124_ovl14, which had a wrong data map as well. All 4 banked as own C, SHA green.
A lasting tool fix would pass carve the body text with the renames applied, not the member text.
