# C0299 — Symbol address lui hoisted above a constant store: reuse one s32 local for both
tags: codegen,sched,sched1,hoist,lui,address,local,reuse,regalloc,v0-v1 · date: 2026-11-01 · phase/task: 3.4/T17 · origin: W82 F7938_ovl00

symptom: sched1 hoists the `lui` of a symbol address above a constant store. The constant then takes `$v1` and not `$v0`, and the address pairs swap registers.

cause: a fresh local for the address is inert. Constant propagation puts the address into the store, and sched1 moves the `lui` freely. A local with two definitions is one pseudo. Its second definition cannot move above the first use.

lever: reuse one `s32` local for the constant and then for the address. Write `v = 0x10; obj[0x16] = v; v = (s32)D_X; *(s32*)(obj + 0x68) = v;`. If a second address pair is also out of order, reuse a second local the same way.

## Instance
W82 rockx5 func_800F7938_ovl00 (c28) matched at try 19. The reuse of `v` took the diff from 7 to 6 words. A second reused local `w` (first the 0x42 value, then `(s32)D_800FB59C_ovl00`) gave the match. A do-while fence (C0294) on the 0x16 store gave 86 words. This is one datapoint.
Near: C0273 (a reused `s32` local keeps `andi 0xFF`), C0242 (the declaration order of base locals).

## Extension: one local for a run of stored values (W84)
W84 rockx5 func_80100224_ovl04 (c48) is a second datapoint. One reused `s32` local `v` takes 6, 8, `(s32)D_80076B00`, `(s32)D_80102F5C_ovl04` and 1. Each value is set just before its store.

Then sched1 does not hoist the `li` constants and the `lui` chains, and all values stay in `$v0` in source order. This took the diff from 18 words to the match at try 11.
Keep the 0x30 store direct. Through `v`, its `lui` moved above the 0x42 chain (32 words).
Rider (T19.c50, `harvest.py rider`, strip = each value stored directly, with no `v`): load-bearing on rockx5 func_80100224_ovl04 (banked W84).

## Extension: a reused local before a load (W86)
W86 slus func_800414F0 (c5) is a third datapoint. Here the second definition is a load, not an address. Write `v = 0x37; obj[5] = v; obj[6] = 0; v = *(s8*)(obj + 0x14B); if (v == -1)`.
Then sched1 does not hoist the `lb 0x14B` above `sb 5`, and 0x37 and the byte both use `$v1`. This gave the match at try 12.

A do-while fence (C0294) on the 0x37 store stopped the hoist, but 0x37 stayed in `$v0` (18 words). A volatile read gave `lbu` and a sign extension (19 words).
Rider (T21.c50, `harvest.py rider`, strip = `obj[5] = 0x37;` with no `v`): load-bearing on slus func_800414F0 (banked W86).
