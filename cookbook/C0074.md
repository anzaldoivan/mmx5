# C0074 — Compare operand written first is loaded first: write the global first to flip the loads
tags: idiom,cse_expr,operand-order,compare,slt,load-order,branch-sense · date: 2026-10-06 · phase/task: 1.8.2/T5 · origin: docs/codegen-map/levers.yaml expr_compare_load_order

symptom: the two loads feeding an `slt` issued in the opposite order (or slt operands / branch sense flipped)
lever: expr_compare_load_order

## Residual
The residual is a relational test between a struct field and a global. Ours loads the field first, but the target loads the global first. The tell regex (levers.yaml `expr_compare_load_order`) is the field `lh` immediately before the global's `lh`. It matches the before and is absent in the after. The diff of rockx5 func_800EFEF4_ovl12 written `e->y < D_8009A0AA` is 2 of 23 words (slt, beqz).

## Mechanism
The pass group is `cse_expr`. The function do_jump hands LT/GT to compare (`gcc/expr.c:11274`), which expands operand 0 before operand 1. So gcc emits the load of the written left operand first, and this operand becomes the slt's first source. `a < b` and `b > a` are the same test with swapped expansion order.

## Lever
Write the comparison with the operand the target loads first on the left (`G > s->y` instead of `s->y < G`). For `!(a<b)` vs `b<=a`, see T4.c12 (that choice also changes cross-jumping). Hoisting a field into a local before the test also puts its load first (T4.c46).
