# A swap rename is a no-op under #define: bank the call-swapped twin as its own C

Problem: masked-only twin calls f then g where the rep calls g then f. Reloc rename map = {g: f, f: g}.
`#define g f` + `#define f g`: cpp never re-expands a macro inside its own expansion, so both calls stay as the rep.
Masked compare passes (jal fields masked). The whole-binary SHA fails at link (`ROCK_X5.BIN: FAILED`).

Detect: rename map where a target is also a source (`set(ren) & set(ren.values())`).
propagate.py reloc_gate refuses it since 3.4/T3: `cyclic rename <a> -> <b>`. Sweep showed 24 such members.

Fix: bank the twin standalone: copy the rep body, swap the calls per the twin's asm, `carve.py apply ... --body <copy>`.
Ex: rockx5 func_800F6348_ovl28 (twin of func_800F6114_ovl28), 3.4/T3. See C0146 (rename idiom).
