# C0170 — Swapped arg registers: a new variable for a derived value splits the live range
tags: codegen,regalloc,global-alloc,live-range,move,a0-a1,temp · date: 2026-10-20 · phase/task: 3.3/T7 · origin: W29 FB6A0

symptom: two values are in swapped argument or temporary registers (the target opens with `move a1,a0`). Ours keeps the object pointer in `a0`.
lever: put a derived value in a new variable (`sq = d * d`) instead of reassigning the old one (`d = d * d`).

## Residual
W29 FB6A0_ovl06: `d = d * d; o->x2C = 0x500000 / d;` keeps one long live range for `d`. Global alloc then gives `o` the first register.

## Lever
`s32 sq; sq = d * d; o->x2C = 0x500000 / sq;`. The split live range changes the global-alloc priority, so `d` takes `$a0` and `o` moves to `$a1`, as in the target.
A plain local copy of the object pointer (`o = arg`) is coalesced and has no effect.

## Extension: a base local for a derived pointer (W85)
W85 rockx5 func_800FA004_ovl50 (c10) is a second datapoint. The loop counter and the loop pointer were in swapped registers (`i` in `$a1`, `q` in `$a0`).
