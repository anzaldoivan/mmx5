# C0259 — Table index ending in +1 folds into the lbu offset: compute the index in its own s32 local
tags: codegen,index,table,local,s32,lbu,offset,fold,addiu · date: 2026-10-25 · phase/task: 3.3/T36 · origin: W58 slus 8002AA7C

symptom: a byte table is read at a computed index that ends in `+ 1`. Ours folds the 1 into the `lbu` offset (`lbu v0,1(v0)`). The target adds it with its own `addiu` before it adds the table base.

lever: compute the index as its own `s32` local statement, then read the table with it. Write `s32 i = p[0xC] * 4 + p[0xD] * 2 + 1` and then `arg0[4] = t[i]`. The inline subscript `t[C * 4 + D * 2 + 1]` lets expand move the constant into the address.

## Instance
W58 slus func_8002AA7C (c33), match at try 5. Declare the table base local first (`u8* t = D_80071B0C`) to get the target `lui` order.
Rejected: `(C * 2 + D) * 2 + 1` puts the `sll` after the add. A 2D view `u8 T[][4]` with `T[C][D * 2 + 1]` and a `u8 (*t)[4]` local fold the 1 again.

Related: C0075 (a temp local blocks a constant fold in a subtract). C0231 (a separate `p += n` keeps its own `addiu`). C0242 (declare base locals in the target order).
