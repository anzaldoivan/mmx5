# C0070 — Extra move copy into $s: a dead reassignment of the source ends CSE copy-propagation
tags: idiom,cse_expr,dead-store,copy-propagation,move,callee-saved,canon-reg · date: 2026-10-05 · phase/task: current/T6 · origin: docs/codegen-map/levers.yaml cse_copy_dead_reset

symptom: an extra `move $s,$t` copy where ours keeps one pointer in `$s`
lever: cse_copy_dead_reset

## Residual
Ours computes a pointer straight into a callee-saved reg (`addu $17,$16,128`) and uses it there; the target computes it into a temp (`addu $3,$16,128`), uses the temp, and copies it with `move $17,$3` later. tell regex (levers.yaml `cse_copy_dead_reset`): `^\s*addu\s+\$1[6-9],\$\d+,128\b` -- matches ours (before), absent in the after. Without the lever slus func_80053A4C diffs 59 of 71 words.

## Mechanism
Pass group `cse_expr`. With `p = q;` and q set once, cse records p and q as equivalent and canon_reg (`gcc/cse.c:2720`, staged tree refs/gcc-2.95.2-psx/) rewrites every use of p to q; p's copy dies and q alone crosses the call into `$s`. A second store to q later on the path (`q = tbl;`, never read) ends the equivalence there, so the uses of p after it keep p: p crosses the call in `$s`, q stays short-lived in a temp, and the copy survives as `move`. flow deletes the dead store afterwards, so nothing of it shows in the asm. Dump: pseudo for p is gone from `.cse` onward in the before side and survives to `.lreg` in the after side.

## Lever
add a dead reassignment of the copied-from variable after the copy (`q = <anything>;` with q never read again), before the uses of the copy that must stay separate. It looks like junk: keep it with a comment that names this entry.
