# C0313 — Constant 1 in the wrong reg, later regs off by one: a redundant same-value store in the next arm
tags: codegen,regalloc,global-alloc,constant,store,redundant,FAKE,reload_cse · date: 2026-11-06 · phase/task: 3.4/T23 · origin: W88 FA60C_ovl39

symptom: a constant 1 and a global base trade registers at a byte store. The target holds the 1 in `$a3` and `%hi` of the base in `$a2`. Ours puts the 1 in `$v0`, and each later register is off by one.

cause: a constant used in two blocks with a short range in each stays a local pseudo. Local-alloc then gives it the first free register. A second use across the branch makes the pseudo global, so global-alloc places it. After reload, reload_cse deletes a store that writes the same value again.

lever: in the next arm, write the same store again (`base[0xA0] = one;`). Mark it `// !FAKE: redundant store (deleted post-reload)`. Place it where the target's order needs it.

## Instance
W88 rockx5 func_800FA60C_ovl39 (c26) matched at try 8. The redundant store before the `0x96` store gave a 6-word diff with `$a2` and `$a3` swapped. After the `0x96` store, it gave the match. This is one datapoint.
Near: C0306 and C0272 (a constant held in a local).

## Byte proof
Rider (T23.c50, `harvest.py rider`, strip = no redundant store in the `== 0x1F` arm): load-bearing on rockx5 func_800FA60C_ovl39 (banked W88).
