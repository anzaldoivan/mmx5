# C0293 — Stack copy with andi 3 and lwl/lwr loops: struct assignment of a u8-only struct
tags: codegen,struct,struct-copy,block-move,lwl,lwr,stack,rodata,table · date: 2026-11-01 · phase/task: 3.4/T14 · origin: W79 F38F4_ovl26

symptom: the target copies a read-only table to the stack. For a large table, it tests the alignment with `andi 3` and then runs a `lwl`/`lwr` loop or a `lw`/`sw` loop of 16 bytes. For a 9-byte table, it emits `lwl`/`lwr` and `lb`.

cause: gcc emits a block move for a struct assignment. The block move selects the aligned loop or the unaligned loop at run time when the alignment is not known.

lever: declare a struct type that has only a `u8` array, at the size of the table. Copy the table with a plain struct assignment: `a = D_800EE9A8_ovl26;`. Do not write a copy loop, and do not invent initializer bytes.

## Instance
W79 rockx5 func_800F38F4_ovl26 (c30) copies two 0x30-byte tables with `typedef struct { u8 b[3][16]; } Tbl800EE9A8;`. It matched at try 1.
W79 rockx5 func_800F39A8_ovl28 (c1) copies a 9-byte table with `struct { u8 b[3][3]; }`.
At bank time, move each new struct type to `include/types.h` (C0084).
