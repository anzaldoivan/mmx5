# C0245 — Table base picked by a branch, addu operands swapped: hold the base in an s32 local
tags: codegen,addu,operand-order,base-pointer,s32,local,index,rtl-shape · date: 2026-10-25 · phase/task: 3.3/T30 · origin: W52 slus 8003FE04

symptom: a table picked by a branch and indexed by an argument has its `addu` operands swapped. Ours gives `addu v0,v0,a1` and the target gives `addu v0,a1,v0`. Writing `*(a1 + t)` changes nothing.

lever: hold the chosen base in an `s32` local, `t = (s32)D_A`, and read `*(s8*)(a1 + t)`. The integer sum has another RTL shape, so gcc emits the operands in the target's order.

## Instance
W52 slus 8003FE04 (c20), match at try 3. Try 1 with `s8* t` and `t[a1]` was 1 word off at +0x38. Try 2 with the source order flipped did not move it.
Related: C0073 (commutative operand order follows RTL shape), C0078 (pointer plus index form).
