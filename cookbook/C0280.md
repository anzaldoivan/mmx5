# C0280 — Byte table indexed x*25 + y*5 + z adds in the wrong order: declare it u8 D[][5][5]
tags: codegen,array,3-d,index,table,u8,stride,add-order,regalloc · date: 2026-11-01 · phase/task: 3.4/T9 · origin: W74 F2038_ovl00

symptom: a byte table is read at `x*25 + y*5 + z`. The target sums the inner terms first, `(z + y*5) + x*25`, then adds the base. Ours with a flat `u8 D[]` index adds `x*25` first, and the address registers swap.

cause: gcc expands a multi-dimensional array reference from the innermost subscript out. A flat index follows the source order of the `+` terms.

lever: declare the table with its real shape, `extern u8 D[][5][5];`, and index it `D[x][y][z]`. The row strides come from the type.

W74 rockx5 func_800F2038_ovl00 (c18). The flat `x*25 + y*5 + z` index with a local table pointer gave diff 40 of 65 at try 1. The 3-D table matched at try 2.
