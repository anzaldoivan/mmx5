# Find why a red CI gate passed the local hooks

The psxdecomp-readme job judges `BASE..HEAD` with the tools of `BASE`. Local hooks judge each commit with the tools of `HEAD`.
If the job is red and the hooks were silent, test the three causes in this order.

1. Get the base and the findings of each red run. Use `gh api repos/<o>/<r>/actions/jobs/<id>/logs` and grep `BASE:` and `GATE`.
2. For each commit that added a finding, copy the judge from its parent. Use `git show <c>^:tools/psxd_floor.py` and the same for `psxd_publish.py`.
3. Run `python3 -I <judge>/psxd_floor.py gate --ci <c>^..<c>`. A FAIL here shows that the tool copy is not the cause.
4. Run the push judge on the pushed range: `gate --push <base>..<head>`. A FAIL here shows that the range is not the cause.
5. If both fail, a hook was absent or skipped. Look at the hook file times in `.git/hooks/`.

The style gate counts the whole public tree, not the diff. After one bad commit, a present hook refuses every later commit.
A long run of commits that landed is therefore proof that `pre-commit` was absent.

To check a tree before CI, run `make style-check`. It runs `gate --ci origin/main..HEAD` with the tools of `origin/main`.
