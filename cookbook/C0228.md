# C0228 — One call on two paths, a0 move in a beq slot: write one call per arm, gcc merges them
tags: codegen,cross-jump,tail-merge,cse,call,a0,delay-slot,if-else · date: 2026-10-24 · phase/task: 3.3/T25 · origin: W47 slus 8003F2D8

symptom: the target has one call on two paths, and the jump path skips a shared `move a0` that sits in a `beq` delay slot. Ours has one call with an extra `move a0,s1` at the join and a `nop` in the `beq` slot (diff 15 of 33 words).

cause: the target's RTL had two calls, one per arm, with different second args. CSE (follow-jumps) drops the redundant `$4 = obj` on the first path, cross-jump merges the call tails, and the remaining a0 move fills the `beq` slot. One call written after the tests never has the redundant move to drop.

lever: write one call per arm, though the target shows one call. Example: `if (A) { s = x; f(obj, arg1, k); x = s; } else if (B) { s = x; f(obj, n, k); x = s; }`. gcc tail-merges them into the target's one call.

## Instance
W47 slus 8003F2D8 (c13): one shared call (try 1, try 3 with a marked goto) gave diff 15. Two calls inline in the compare gave 23 (try 2). Two calls per arm with `n = arg1 + 0x70` hoisted before the if matched (try 4).
Related: C0192 (the opposite case: the target keeps a call on each path), C0050 (cross-jump law).
