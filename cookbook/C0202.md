# C0202 — Table index from a just-stored byte keeps andi 0xFF: index by the stored field, not the local
tags: codegen,cse,store-forward,u8,andi,table,index,field · date: 2026-10-24 · phase/task: 3.3/T19 · origin: W41 slus 8003D5E0

symptom: a table index from a byte that was just stored has an extra `andi 0xFF` before the `sll 2`. Ours indexes with the local and has no `andi`.

cause: the target indexes by the stored field. CSE forwards the store to the reload, and the forwarded value is zero-extended again for the u8 read.

lever: index by the field just written, not by the local that holds the value: `arg0[0xFA] = v; x = *(s32*)(D + arg0[0xFA] * 4 + 0x88);`.

## Instance
W41 slus 8003D5E0: indexing by the local `v` gave diff 36/42 words. Indexing by `arg0[0xFA]` gave 1. The last word was the `addu` base/index order. It matched when the global was named directly in that one address sum, while the other reads kept the local base.

## Byte proof
Rider (T19.c50, `harvest.py rider`, strip = index by the local `v`): load-bearing on slus func_8003D5E0 (banked W41).
