# C0262 — Long list in a make recipe hits MAX_ARG_STRLEN (128 KiB per sh -c arg): pass it through a file
tags: make,shell,argv,e2big,max_arg_strlen,recipe,build · date: 2026-10-26 · phase/task: 3.3/T4 · origin: T4 generalizable (c49 no-rom compile-only)

Problem: a make recipe expands a long list (`$(SRC)`, thousands of paths) inline into one `sh -c` command. Linux caps one argv string at MAX_ARG_STRLEN = 131072 bytes (32 pages), whatever `ARG_MAX` says. Past it the recipe dies with `/bin/sh: Argument list too long` (E2BIG), only once the tree grows big enough.

Lever: write the list to a file with GNU make's `$(file >path,$(LIST))` (no shell involved), then iterate in the shell with `for x in $$(cat path)`. The command substitution happens inside the shell, so no argv string carries the list. `xargs` over the file also works.

## Instance
3.3/T4 (c49): `make no-rom` compile-only ran `for c in $(COMPILE_SRC)`, 4149 paths = 131427 bytes, and broke the gate. Fix in `mk/fleet.mk` compile-only: `$(file >$(CO_DIR).list,$(COMPILE_SRC))` then `for c in $$(cat $(CO_DIR).list)`.

Related: C0028 (make under dash has no pipefail, so stage compiles through files).
