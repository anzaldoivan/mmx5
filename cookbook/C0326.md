# C0326 — Table field offset folded into %lo(D+off): index a struct view, not a u8[] byte offset
tags: codegen,struct,view,array,index,lhu,offset,fold,hi-lo,table · date: 2026-11-07 · phase/task: 3.4/T26 · origin: W91 slus 80039F1C

symptom: the target reads a table field as `lhu 0xA(base)` after it computes the row address. Ours folds the 0xA into `%hi`/`%lo(D+10)`.

cause: a `u8[]` view with `+ idx * 0x54 + 0xA` is plain address arithmetic, so gcc adds the constant to the symbol. An indexed struct array keeps the row address in a register and the field offset in the load.

lever: if the field offset folds into the symbol, index a struct view of the table. Write `D[idx].field`, not a byte offset from the table base.
