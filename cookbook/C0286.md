# C0286 — Sparse switch tree with the wrong slt root: an empty !FAKE extra case rebalances it
tags: codegen,switch,case-tree,decision-tree,slt,balance,empty-case,FAKE,jump · date: 2026-11-01 · phase/task: 3.4/T12 · origin: W77 F6324_ovl00

symptom: a switch over sparse values becomes an `slt` compare tree with the wrong root. The target tests the middle value first, and ours tests a neighbour.

cause: gcc 2.95 balances the case tree by the count of case nodes. Four nodes {0,1,2,0x70} give root 1. Five nodes give root 2.

lever: add one empty case after the last case, marked `// !FAKE:`: `case 0x71: break;`. Its `beq` to the exit duplicates the next `j exit`, so jump opt deletes it. The tree keeps the new root.

## Instance
W77 rockx5 func_800F6324_ovl00 (c45), a switch on a state byte over {0,1,2,0x70}, no jump table. The extra case at the end matched at try 7. The same extra case at 3 left a live `beq` in the tree.
Near: C0072 (switch body layout follows case order), C0251 (a GNU case range for an `slt` test chain).
