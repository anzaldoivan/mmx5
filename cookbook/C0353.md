# Ledgered head with a matched X6 twin: port the donor C, drop X6-only headers, try 1

When: a failed (ledgered) X5 head has an X6 donor in state c in `docs/oracle/x6-leads.tsv`.
Do:
- Put the keys in a file. Then run `waves.py port W<k> --targets <file>`. The wave.json comes from the list, and ledgered keys are allowed.
- If the port prints `error cpp`, look for an X6-only include (`psyq/*.h`, `mmx6/*.h`, `../shared/*.c`). Drop it. Declare each callee as X5 `src/` declares it. Take types from `include/types.h`.
- If the port prints `error symbol D_...`, an X6 global in the seed has no X5 name. Write the draft by hand from the donor function only. Remap the globals by asm position (C0347).
- If the port prints `error cc1` on an X6 struct, read the fields through offset casts that match the target loads. An existing `types.h` struct also works.
- If the donor has `register asm` pins, keep them. Mark each pin `// !FAKE:`.
- A function-pointer argument keeps its X6 address through the port, and try masks it. Before the gate, compare every `func_` and `D_` in the draft with the target asm relocations (C0137).

Evidence: 3.6 T1, waves W98-W100. All 21 rows matched under try. 8 matched at the port, and 13 matched by a coder from the seed or the donor. The mean coder context was 40k, against 57.7k for a fresh draft. Rows capped at 30 tries in W77, W79 and W96 matched in 1 try.

In W99, 8001A7A8 had a red SHA from two X6 callbacks. It banked in W100 after a rename by asm position. Pins were needed for 800133A8, 800133E0 and 8003ACF0.
