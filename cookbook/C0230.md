# C0230 — Two-value state picked by a test with a call: if/else after the call, arms in fall-through order
tags: codegen,branch-polarity,if-else,call,callee-saved,state,sltiu,u32 · date: 2026-10-24 · phase/task: 3.3/T25 · origin: W47 F4658

symptom: a two-value state (8 or 9) is picked by a test that includes a call. With `state = 8; if (a) { if (b) state = 9; }` before the call, the state sits in an s-register across the call (diff 33 words). With an if/else after the call, the branch is inverted and the state is in the wrong register (diff 5 words).

lever: assign the state in an if/else after the call, and order the arms by the target's fall-through. The arm that falls through in the asm (here 9) is the else arm, and the delay-slot arm (8) comes first: `if (x >= D / 2 || (u32)(f() & 0xF) < 8) state = 8; else state = 9;`. A `(u32)` cast gives the `sltiu`.
