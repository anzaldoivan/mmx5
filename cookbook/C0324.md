# C0324 — Global base lui lifted above u16 field loads: store through a local struct view
tags: codegen,sched,sched1,alias,struct,view,s16,store,hoist,lui · date: 2026-11-07 · phase/task: 3.4/T26 · origin: W91 FF4D0_ovl04

symptom: a global base `lui` is lifted above the `lhu` field loads of another object. The halfword stores off that base come out in the wrong order (18 words).

cause: `s16` stores and `u16` loads through `u8*` casts share one alias set. sched1 keeps them in order and lifts the base address instead. A struct-typed store has its own alias set, so the loads move freely past it.

lever: if the store base is hoisted above the field loads, declare a local struct view of the global. Store through its `s16` members, not through `*(s16*)(base + off)`.

## Instance
W91 rockx5 func_800FF4D0_ovl04 (c28) matched at try 10. The view `D_8009A1F8_5E_t` has `pad[0x5E]`, `s16 unk5E`, `pad[2]` and `s16 unk62`. It took the diff from 18 words to 7. Then the 0x62 store written in each arm, with no join local, closed it (C0196).

A `u8[]` offset store anchored the base at `%hi(D+0x94)`. Use a pointer local to the global symbol.
At bank time, move the view type to `include/types.h` (C0084).
Near: C0060 (load stuck below a store), C0243 (typed view for a store run).
