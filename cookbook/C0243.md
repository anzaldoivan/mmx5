# C0243 — Constant regs off at a struct store run: typed view, then try source orders
tags: codegen,sched,store-order,struct,view,li,v0-v1,constant-store · date: 2026-10-25 · phase/task: 3.3/T30 · origin: W52 FAA20_ovl57

symptom: a run of constant stores to one global gets its `li` constants in the wrong registers. The target holds 0x100 in v1 and 1 in a0, ours swaps them. Asm order and the C0234 reverse order both stay off.

lever: address the global through its typed struct view, then try source orders of the stores. With the typed view the scheduler moves the stores freely, so the source order sets which constant takes which register.

## Instance
W52 FAA20_ovl57 (c10), match at try 9. The u8[] view in asm order was 3 words off, and the C0234 reverse order was 6 off. The typed `D_8009A1F8_t` view alone stayed 3 off. Source order B2, B6, F4, 3, 57 matched.
Related: C0234 (reverse of the asm order), C0076 (zero store interleaved between constants).

## Byte proof
Rider (T30.c50, `harvest.py rider`, strip = the +3 and +0x57 stores swapped): load-bearing on rockx5 func_800FAA20_ovl57 (banked W52).
