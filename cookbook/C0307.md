# C0307 — Byte field copied, then indexes a table, andi after sb: index by a fresh read of the source field
tags: codegen,cse,andi,0xff,u8,table,index,field,re-read,sched · date: 2026-11-02 · phase/task: 3.4/T20 · origin: W85 slus 80017348

symptom: a byte field is copied to a second field, then it indexes a table. The target does the `andi 0xFF` before the `sb`. Ours drops the `andi`, or does it after the `sb`.

cause: a `u8` index local lets combine use the known `lbu` range, so the `andi` goes. An index by the stored field (C0202) keeps the `andi`, but sched puts it after the store.

lever: use no index local. Read the source field again for the index. Write `obj[0x48] = obj[0x47];`, then `((u32*)base)[obj[0x47]]`.

## Instance
W85 slus func_80017348 (c44) matched at try 13. The `u8` index local gave a diff of 66 words. The index by the stored field gave 6 words, and the `andi` came after the `sb`. A reused `s32` local (C0273) was inert. This is one datapoint.
Near: C0202 (index by the stored field), C0297.
