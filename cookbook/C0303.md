# C0303 — Slot address with sll and addiu swapped: compute the index local before the base local
tags: codegen,sched,statement-order,index,base-pointer,s32,local,addu,sll,v0-v1 · date: 2026-11-02 · phase/task: 3.4/T19 · origin: W84 EFAF8_ovl24

symptom: the target forms a slot address `arg0 + 0x114 + arg1 * 4` with the `sll` first in `$v1`. Then it does the `addiu` of the base in `$v0` and the `addu`. Ours puts the base first, or combine refolds the sum.

cause: the statement order of two independent locals sets the sched order and the `$v1`/`$v0` roles. A pointer sum, an array form or one `s32` base local (C0245) leaves the order to fold.

lever: put the index in its own `s32` local first, then the base in an `s32` local, then sum them. Write `i = arg1 << 2; b = (s32)arg0 + 0x114; slot = (s32*)(b + i);`.

## Instance
W84 rockx5 func_800EFAF8_ovl24 (c36r) matched at try 11. The forms `base + arg1`, `&((s32*)(arg0 + 0x114))[arg1]` and `(arg1 << 2) + (s32)(arg0 + 0x114)` stayed at 3 words of diff. The `s32` base local alone also stayed at 3 words. This is one datapoint.
Near: C0059 (the MULT comes first in `p[i]`), C0245 (an `s32` base local swaps the `addu` operands).
