# C0310 — Signed /2^n result in the wrong reg: one statement per step on one s32 local
tags: codegen,divide,signed,bias,bgez,combine,statement-split,local,clamp · date: 2026-11-02 · phase/task: 3.4/T21 · origin: W86 800EE9A0_ovl11

symptom: a signed divide by 0x2000 comes out with the wrong registers. The target puts the biased result in a separate register with `addu v0,v1,zero` in the `bgez` delay slot, and the clamp variable stays in `$v1`.

cause: in one expression, combine folds the steps together. `(x*32)/0x2000` folds to a divide by 256. With `v/0x2000 + C` in one expression, the clamp variable moves to `$a0`.

lever: write each step as its own statement on one `s32` local. Write `v = f() + K; v <<= 5; v = v / 0x2000; v += 0xF0;`.
