# C0265 — Two-constant select from a masked test lands in v1: write the test into the join variable
tags: codegen,select,andi,bnez,join-variable,v0-v1,jump,if-else · date: 2026-10-31 · phase/task: 3.4/T4 · origin: W69 slus 80025240

symptom: a byte field gets one of two constants from a masked test. The target keeps the `andi` result, the `bnez` test and the `li` value in v0. Ours puts the value in v1. The delay slot of an earlier `bgez` also fills differently.

lever: write the test into the join variable, then overwrite it in each arm. Use `code = a0[0] & 0x10; if (code != 0) code = 0x2A; else code = 0x28; poly[7] = code;` with `s32 code`.

The condition now mentions `code`. Because of this, jump.c does not rewrite the arms into `code = B; if (c) code = A`. The test and both constants then share one register.

## Instance
W69 slus 80025240 (c48), match at try 14. A preset local, an if/else local, a direct ternary (C0247) and a `u8` local all left the value in v1.
Related: C0247 (store the ternary directly), C0165 (one store per arm).

## Extension: a sign select (W87)
In rockx5 func_800F22C4_ovl03 (c23), the test is a sign test of a word, not a mask. Load the word into the join variable first: `s32 v = *(s32*)(a0 + 0x24); if (v < 0) v = -1; else v = 1;`. The result then lands in `$v0`.
