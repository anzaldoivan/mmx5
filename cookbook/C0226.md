# C0226 — Two arms each n = byte + 1, one in the wrong reg: write both arms as `n = x`, then `n++`
tags: codegen,regalloc,if-else,arm-shape,mirror,increment,lb,v0-v1 · date: 2026-10-24 · phase/task: 3.3/T24 · origin: W46 F609C

symptom: two if/else arms each compute `n = x + 1` from the same byte, then share one store. The target loads the byte in each arm into the same register. Ours loads into `v0` in one arm then `addu` to `v1`. A `||` condition merges the two loads into one at the join.

cause: `n = x + 1` and `n = x; n++;` give different RTL, so the arms get different registers.

lever: write both arms in the same two-statement form, `n = ((s8*)obj)[2]; n++;`, with an explicit if/else (not `||`).

## Instance
W46 F609C_ovl26 (c4): the `||` form gave diff 7. If/else with `n = x + 1` in arm 1 gave diff 2. Both arms `n = x; n++;` matched (try 3).
Related: C0129 (regalloc steering), C0152 (per-branch statements).
