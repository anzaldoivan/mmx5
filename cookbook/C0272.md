# C0272 — Pointer loses s0 to a shared constant: set a local to the constant, compare against it
tags: codegen,regalloc,s0-s1-swap,density,constant,local,compare,callee-saved · date: 2026-10-31 · phase/task: 3.4/T6 · origin: W71 F3EF4_ovl10

symptom: the object pointer must be in `s0`, but ours puts it in `s1`. A constant that several compares use takes `s0`. The constant pseudo wins the density race (C0047).

lever: declare a local and set it to the constant at the top, for example `v = 2`. Compare against `v`. Reuse `v` later for other values. The constant pseudo then merges into `v`, and the pointer takes `s0`.

## Instance
W71 rockx5 func_800F3EF4_ovl10 (c31) matched at try 21. With the layout right, `s0` and `s1` were swapped (39 words). One local `v = 2` for the three `== 2` tests matched. Later the same `v` holds the 0x90 value.
Related: C0047 (callee-saved register order follows use density).

## Byte proof
Rider (T6.c50, `harvest.py rider`, strip = no `v = 2`, literal `2` in the three tests): load-bearing on rockx5 func_800F3EF4_ovl10 (banked W71). A strip that keeps `v = 2` and compares against a literal `2` is inert. The initialisation carries the lever, not the spelling of the compares.
