# C0191 — Global compared with a field loads late: put the global on the left of the compare
tags: codegen,compare,operand-order,global,load-order,regalloc · date: 2026-10-24 · phase/task: 3.3/T17 · origin: W39 F6820

symptom: a compare of a global against a field. The target loads the global first (into a0, `%hi` in v1). Ours loads the field first, with the wrong lw order and registers.

cause: gcc expands the compare operands left to right. The operand written first is loaded first and gets the first free register.

lever: write the compare with the operand the target loads first on the left, flipping the relation (`G > obj->x`, not `obj->x < G`).

Related: C0073 (commutative operand order), C0051.
