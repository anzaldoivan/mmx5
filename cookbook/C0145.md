# Fresh-clone proofs start from the public projection

- Build the proof tree from the release projection of HEAD. Use `psxd_publish list --rev` and `git archive` into its own git repo. Do not `git clone` the dev repo.
- Why: a dev clone holds private-but-tracked dirs (waves/, agent files). They hide missing-dependency bugs.
- Example: 2.7/T5 found tools-health rungs that needed waves/. It also found a dump path that failed only on the projection.
- Then run only the README's commands in order. Assert that the final artifact (for example the patched cue) exists.
- See C0095 (one-pass fresh clone) and tools/fresh_clone.sh.
