# Saved-register order of two constants: a do-while(0) fence weights a use

Tell: two values kept across calls (constants or locals) sit in swapped saved registers (`$s4`/`$s5`). Declaration
order, types and extra locals change nothing. The value with more uses takes the lower register (C0047). gcc
global.c `allocno_compare` ranks by refs / live length.

Move: wrap a store of the value that must rank higher in `do { ... } while (0); // !FAKE:`. In flow.c, gcc adds
`loop_depth` to `REG_N_REFS` for each use inside the loop, so a use in a fence counts double. A nested fence counts
triple. Use it to lift one value above another in the ranking.

Cost: a fence edge also stops the scheduler from moving instructions across it. Put each edge where the target
already has a break in its order. Split a load so its address `lui` stays on the right side of the edge. Inline
helper parameters used inside a fence are not replaced by constants, so write the fenced call site out with literals.

Evidence: 3.6 T5 W102 slus func_8001B984 (992 insns) went from diff 7 to 4 with three fence weights. The rest was
block temporaries, so it is not a match yet. One datapoint. Related: C0047, C0294, C0129.
