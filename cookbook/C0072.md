# C0072 — Switch body layout follows case order in source: write the cases in target order
tags: idiom,cse_expr,switch,case-order,block-layout,jump,bne,beq · date: 2026-10-06 · phase/task: 1.8.2/T5 · origin: docs/codegen-map/levers.yaml switch_case_source_order

symptom: a beq/beq/j compare chain with the case body inline where the target falls through `bne r,K` tests
lever: switch_case_source_order

## Residual
Small switch (2 cases + default) on a call result. Ours: `beq r,1; beq r,2; j default`, one case body placed out of line. Target: `bne r,2,next` falling into the case-2 body. tell regex (levers.yaml `switch_case_source_order`): `^\s*beq\s+\$3,\$2,\$L\d+` -- matches the before, absent in the after. rockx5 func_800F06BC_ovl04 with case 1 written first: diff 62 of 73 words; func_800FDC6C_ovl07: 35 of 47.

## Mechanism
Pass group `cse_expr` (expand + jump). expand_end_case (`gcc/stmt.c:5001`) emits the compare tree over the value-sorted case list, but the case bodies stay in source order; jump opt then inverts each test whose taken target is the next body, so the source order of the bodies decides which tests become fall-through `bne`.

## Lever
Write the cases in the order the target lays the bodies out (here case 2 before case 1). Case values do not need to be ascending.
