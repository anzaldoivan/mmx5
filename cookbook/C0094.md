# Detect stdlib shadows with -S plus venv site-packages
symptom: a tools/ module named like a stdlib module (types, wave) works under a normal interpreter
- site.py preloads stdlib `types`, so a sibling `types.py` stays hidden. Only `python -S` puts the script dir first.
- Bare `-S` drops site-packages (rabbitizer etc.) and fails for unrelated reasons.
- Detect: run `PYTHONPATH=<venv>/lib/python3.x/site-packages make tools-selftest PY="<venv>/bin/python -S"`.
- Prevent: no tools/**/*.py basename is in sys.stdlib_module_names.
