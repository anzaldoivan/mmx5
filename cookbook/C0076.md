# C0076 — Constant stores alternate v0/v1: interleave a zero store to keep v0
tags: idiom,regalloc,v0-v1,constant-store,li-sb,local-alloc,store-order · date: 2026-10-06 · phase/task: 1.8.2/T5 · origin: docs/codegen-map/levers.yaml regalloc_const_store_interleave

symptom: constant `li;sb` pairs alternating `$v0`/`$v1` (or a third reg) where the target reuses `$v0`
lever: regalloc_const_store_interleave

## Residual
A run of constant byte stores (object init prologue). Ours: consecutive constant temps take different hard regs; target reuses `$2`. tell regex (levers.yaml `regalloc_const_store_interleave`): `^\s*li\s+\$5,1\b` -- matches the before, absent in the after. rockx5 func_800F6E78_ovl04 with two constant stores made adjacent: diff 9 of 335 words.

## Mechanism
Pass group `regalloc`. local-alloc's INSN_SCHEDULING lifetime extension (`gcc/local-alloc.c:1415`) makes a qty conflict with qtys born or dying next to it, so a constant temp cannot take the hard reg freed by the immediately preceding insn; back-to-back constant stores alternate regs. A `$0` store between them puts an insn in the gap and the reg is reusable. sched2 later lifts the li->sb chains above the plain stores, so the visible order differs from the source order.

## Lever
Interleave a zero (or shared-constant) store between consecutive constant stores; order the statements so every constant store is separated by one. The visible asm order is not the source order (sched2).
