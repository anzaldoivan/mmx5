# C0329 — Arm temps in different regs, target shares one: one s32 temp in both arms, cast in one
tags: codegen,regalloc,global-alloc,temp,local,if-else,cast,pointer,s32 · date: 2026-11-07 · phase/task: 3.4/T27 · origin: W92 EF39C_ovl21

symptom: in an if/else, each arm reads one value into a temp. The target uses the same register in both arms. Our build uses different registers.

cause: a temp set in both arms is a global pseudo. It has no birthing boost, so global alloc gives it the same register in both arms. Two temps, one per arm, are allocated apart.

lever: if both arms need one temp register, use one `s32` temp in both arms. In an arm that needs a pointer, cast it there, as `(u8*)t`.

## Instances
W92 rockx5 func_800EF39C_ovl21 (c8) matched at try 18. The then-arm reads byte 0x2 into `t`. The else-arm reads the 0x5C pointer into the same `t` and copies from `(u8*)t + 0x18`. This closed the last 8 words. A then-only local, or a temp set twice, was inert or worse.
Near: C0052 (birthing boost, the flag read in this draft), C0273 (reuse an `s32` local for a full-width value).
