# C0178 — Load placed too late: read the value into a local where the target loads it
tags: codegen,sched,load,local,alias,branch,hoist,store-order · date: 2026-10-21 · phase/task: 3.3/T10 · origin: W32 FCBB0 EF140

symptom: the target issues a load early. Ours comes out late, after a byte store or inside a branch arm.
lever: read the value into a local where the target loads it.

## Residual
W32 FCBB0_ovl39: `arg0[6] = 0;` written before the table read `D_800FEB34_ovl39[...]`. The u8 store may alias the table, so gcc keeps the load after it (diff 15/28).
W32 EF140_ovl09: `obj->unk80[obj->unk2 + 0xF] = 0;` inside `if (obj->unk95 != 0)` places `lw 0x80` after the `beqz` (diff 17/27).

## Lever
FCBB0: `c = D_800FEB34_ovl39[...];` first, then `arg0[6] = 0; arg0[5] = c;` matched.
EF140: `u8* p = obj->unk80;` before the inner if, `p[obj->unk2 + 0xF] = 0;` inside it, matched. The scheduler puts the `lw` ahead of the branch.
